# Repository instructions

These instructions govern maintenance of Skills Lab within the owner's current task authority. Their presence grants no external effects and does not govern consumers' unrelated projects.

1. Resolve the exact task, owner authority, source revision and current repository state before acting. This repository distributes selected instruction skills; do not introduce unrelated private records or dependencies.
2. For governed repository changes, use Initialize/Initiate to build the authorized candidate, Validate to challenge the actual result and Approve to record the owner's decision and complete only its included effects. Routine steps within an unchanged grant need no repeated approval. Read-only answers and orientation need no new cycle.
3. Assign one writer to each mutable target. Separate author checks from review; disclose actual independence and reduced assurance. An author's review of its own work is not independent.
4. Preserve one controlling source per skill identity. Change the controlling source first under its applicable authority, then prepare the selected export. Do not silently make this copy and another copy competing editable sources. Update inventory and catalog consistently; changed bytes do not inherit an old approval.
5. Keep all resources a skill needs. Preserve its role, trigger exclusions, authority boundaries and required summary format. Invocation metadata does not grant operational authority or attest a backend.
6. After the separately authorized initial seed, prepare source changes through a reviewable pull request and the repository's actual protected integration rules. Do not infer merge, release, settings, licence, hosted-CI, spending or publication permission from candidate preparation.
7. Keep public inclusion explicit. Inspect file contents, package resources and any channel-generated exposure before publication. Retain restricted review evidence outside the public tree; use truthful public provenance without leaking restricted paths or accounts.
8. Verify exact final files and resulting state. On changed inputs, denial, conflict or an unknown external outcome, hold the affected action and reconcile through permitted reads before an allowed retry. Preserve attempts; do not blindly repeat, force push, delete or silently roll back.

Read [CONTRIBUTING.md](CONTRIBUTING.md) for maintenance and [RELEASING.md](RELEASING.md) for publication preparation. Read [RIGHTS.md](RIGHTS.md) before considering distribution rights. No hosted workflow, installation or external action is commissioned by these files.
