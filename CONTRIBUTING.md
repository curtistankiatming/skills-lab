# Contributing to Skills Lab

Start with the [repository instructions](AGENTS.md) and an exact assignment. A contribution proposal is not owner approval or permission to publish it. Collection 1.1.0 selects four skills; it is not a complete inventory of every skill its maintainer has created.

## Prepare a useful change

Identify the affected skill, its controlling source and exact revision, the user request it should serve, and the intended change. Describe changes to triggers, resources, behaviour, compatibility, authority or rights. Work within the assigned writer scope and preserve unchanged resources.

For a selected export, revise the controlling source through its own current authority before updating this copy. Do not patch a distributed copy and silently diverge from the source. An intended transfer of canonical ownership needs an explicit owner decision and a recorded revision boundary.

Update the catalog, inventory and distribution version when their basis changes. Hash final raw bytes; state which files a manifest covers and exclude its own bytes explicitly. Keep historical issued versions and any private review evidence with their accountable owner.

Prepare source, selected export and included index upkeep together before review. Complete the approved task's included upkeep without duplicate approval prompts for unchanged bookkeeping. A new semantic, rights or destination change receives affected review. Adding Scope Pull does not expand an existing three-skill bundle's membership.

## Check and review

Use proportionate permitted checks: complete inventory, source equality where an unchanged export is claimed, valid frontmatter and agent metadata, required resources, working local links and public exposure. A file-format check does not prove runtime behaviour. Do not install, load into active discovery, run model comparisons or contact a service merely to review text.

Have a separate reviewer assess authored changes when the governing assignment requires it; report actual assurance honestly. Resolve findings on the exact candidate and rerun affected checks. Follow the preserved [chat-summary format](skills/governed-task-lifecycle/references/chat-summary.md) for owner-facing lifecycle results.

## Rights and external effects

Before accepting or distributing a contribution, establish permission for its exact included material and the selected outgoing terms. Do not claim that AI assistance, a citation or public availability alone establishes rights. The outgoing licence is [MIT](LICENSE). No separate contributor licence agreement is imposed here; establish permission for included material under the selected terms and preserve applicable notices. See [RIGHTS.md](RIGHTS.md).

Prepare pull requests, integrations and releases only under current authority and actual repository controls. Never include credentials, restricted source links, internal review history, unrelated project material or tool environments in the public payload.
